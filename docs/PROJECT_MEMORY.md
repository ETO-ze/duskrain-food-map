# DuskRain 美食地图项目记忆

更新日期：2026-09-05

## 项目定位

- 网站名称：DuskRain 吕其林美食指南。
- 国内入口使用高德地图，海外入口使用 Google Maps。
- 项目只保存用户自己的评分、评论、图片和店家关联信息。
- 公开首页提供 2026 吕其林指南入口；年度指南使用仓库内版本化 JSON 数据，计划于 2027 年 1 月正式发布 2026 版。
- 管理端负责搜索导入、编辑、删除和评价编写，不负责自动量化交易。
- 管理端“批量新建”支持每行一个商家，格式为“编号 店名 城市或地址 评分 推荐等级 作者 菜系”；多个菜系使用“、”分隔。
- 推荐等级支持“必去 / 推荐 / 一般 / 避雷”；未填写时 `rating >= 8.0` 默认为“推荐”，否则默认为“一般”；作者未填写时默认为吕俊泽。
- 批量新建逐条调用高德搜索和详情接口。信息不完整时使用模糊匹配并采用评分最高的第一个候选。
- 店家去重键包含评分作者：同一 POI 的不同作者允许分别保存；同作者重复导入时合并非空字段，只有信息增加时更新已有记录。

## 当前架构

- 前端：Vite 5 + Vue 3。
- 后端：FastAPI。
- 数据库：SQLite，Docker volume 持久化。
- 部署：Docker Compose，通过网站反向代理暴露 `/food-map/`。
- 国内坐标：GCJ-02。
- 海外坐标：WGS84。

## 管理权限

- `/food-map/admin/` 是超级管理员后台，页面和 `/api/admin/*` 接口均由 Authelia 双因素策略保护，第一因素通过后仍须 Google TOTP。
- `/food-map/developer/` 是独立作者工作台，使用应用内账号与 HttpOnly 会话 Cookie，不开放公开注册。
- 超级管理员填写作者姓名和邮箱后发送 24 小时内有效的一次性邀请；作者通过链接自定义 3-32 位账号名和至少 8 位密码。
- 新密码使用 Argon2id；历史 PBKDF2 密码在成功登录后自动升级。忘记密码通过 1 小时内有效的一次性邮件链接完成，不再生成共用默认密码。
- 普通作者只能读取、创建、修改和删除 `owner_account_id` 属于本人账户的记录；`rating_author` 保留为展示作者名，作者改名不改变稳定所有权。
- 普通作者可使用搜索导入、高德/Google 地图选点和批量新建；批量格式省略作者，前端固定当前作者，后端再次强制覆盖。
- 超级管理员可以邀请、停用、重命名、删除无店家作者并发送密码重置链接；有店家归属时阻止误删。
- 同一 POI 不同作者允许并存，同一作者同店家仍执行去重。
- Google/GitHub 登录只能由已激活作者主动绑定，不会自动创建账户，也不会仅按邮箱自动关联。OAuth 使用随机 `state` 和 PKCE，访问令牌完成回调后不保存。
- 作者可上传 JPEG、PNG 或 WebP 头像，最大 2 MB；服务端重新编码为 WebP 并移除原文件元数据。可信 OAuth 头像仅在作者没有本地头像时导入。
- 手机号身份表和开关已预留，默认 `FOOD_MAP_PHONE_LOGIN_ENABLED=false`，接入短信验证服务前不展示入口。
- 会话、邀请与重置令牌仅保存 SHA-256 哈希；连续登录失败有限流。

## 地图实现

### 国内高德

- 使用高德 JavaScript API 2.0。
- 低缩放级别使用轻量城市汇总点；详细缩放级别只维护一个官方 `MarkerCluster`，内部使用店家标记和统一信息窗体。
- 城市汇总点和数量全部常显；发生碰撞的城市文字自动隐藏，悬停圆点可临时查看完整城市名。
- 管理端可搜索高德 POI、读取详情，也可点击地图热点或空白位置添加。
- 城市聚合只在低缩放级别出现，进入城市后展示单店点和店名。
- 地图移动时可降低道路特征复杂度，停止后恢复完整街道与地名。

### 海外 Google

- 使用 Maps JavaScript API、Places Library、Geocoder 和 AdvancedMarkerElement。
- 管理端文本搜索返回候选列表，必须点击候选项后才写入表单。
- 支持 249 个国家和地区的中英文国家下拉列表。
- 点击 Google 官方 POI 时用 Place ID 补全商家字段。
- 点击非 POI 区域时用 Geocoder 反向解析地址。
- 海外筛选分类来自 Google `provider_category`，不是用户自定义分类。
- 店家点显示评分圆点和完整店名，点击后打开本站统一信息卡。
- 海外筛选、列表和地图点共用 `availablePlaces` 数据集合。国内同步开启时纳入高德店家的全部 `my_categories`，关闭时自动移除对应菜系、城市和作者选项。
- Google Advanced Marker 使用官方 `gmp-click` 事件。列表或随机探店没有 Marker 锚点时先设置 `InfoWindow` 坐标再打开，避免信息卡处于隐藏状态。
- 日夜切换通过保留视野并重建 Google Map 完成，因为 `colorScheme` 只能在初始化时设置。为兼容 weekly 构建，传入稳定字符串值 `LIGHT` / `DARK`。
- 国内与海外公开页都提供“附近店家”“随机探店”“当前视野”、结果数量和条件式重置筛选，公开页不显示管理入口。
- 移动端商家列表在 0-215px 滚动区间渐进收纳：先缩短品牌说明，再淡出地图来源与海外同步项，随后压缩探索操作；筛选器在透明状态切换为横向布局，最终仅保留标题、结果数、重置入口和横向筛选。反向滚动按相反顺序恢复。该行为仅限 860px 以下视口，并通过 `requestAnimationFrame` 直接更新 CSS 变量，避免每帧触发 158 个列表项的 Vue 重渲染。
- 可选同步显示国内店家；坐标先从 GCJ-02 转换为 WGS84。

## 数据字段约定

- `map_provider`: `amap` 或 `google`。
- `country_code`: ISO 3166-1 alpha-2。
- `coordinate_system`: `gcj02` 或 `wgs84`。
- `provider_poi_id`: 地图平台 POI ID。
- `provider_category`: 地图平台分类。
- `owner_account_id`: 稳定的作者账户归属；授权判断优先使用此字段。
- `my_category`: 用户自己的美食分类。
- `my_categories`: 用户自己的多选菜系列表；`my_category` 保留首项用于旧客户端兼容。
- `provider_detail_url`: 对应地图平台详情链接。
- `rating_author`: 默认作者吕俊泽。
- `review_text`: Markdown 风格长篇评价。

## 性能约束

- 不缓存地图瓦片，不把中国地图完整下载到服务器。
- 缓存本站自己的店铺数据、图片地址、评分和评论。
- 地图标记数量增大时优先使用地图官方聚合和 Canvas/WebGL 能力。
- 地图组件卸载时必须清理标记、事件监听、信息窗体和地图引用。
- 移动端默认优先保证拖动和缩放流畅，不增加重型阴影或重复 DOM 标记。
- 公开页只初始化一个可见地图，不创建隐藏预热地图，也不主动预取店家图片。
- 店家图片使用浏览器原生懒加载；列表项使用 `content-visibility` 跳过视口外布局和绘制。
- 公开接口采用网络优先、缓存仅作失败回退，筛选请求带代次标记，过期响应不得覆盖最新筛选结果。

## 隐私与发布

- `.env`、数据库、服务器凭据、备份、构建产物和日志禁止进入 GitHub。
- GitHub 发布采用路径白名单和密钥正则扫描。
- 公开仓库只包含源代码、模板环境变量、README 和技术文档。
- 浏览器 API Key 即使会在网络请求中出现，也必须配置 HTTP Referrer 和 API 范围限制。

## 后续优化方向

- 为 Google 地图配置正式 Cloud Map ID，而不是长期使用 `DEMO_MAP_ID`。
- 当海外店家数量明显增加后，再接入 Google 官方 MarkerClusterer。
- 为平台分类增加稳定的中文别名映射，避免 Google 本地化名称变化造成筛选分裂。
- 超级管理员在高德和 Google 地图之间频繁切换时，可进一步改为销毁非活动地图实例，降低长会话内存占用。
- Vite 生产构建不暴露开发服务器；依赖审计中的开发服务器类告警应在独立升级分支完成 Vite 大版本升级和全量回归。
- 为 README 补充不含隐私信息的桌面端和移动端截图。
- 为邀请与密码重置邮件配置稳定的生产 SMTP，并对投递失败、频率限制和退信建立可观测性。
- 在 Google/GitHub 控制台登记正式回调地址后再启用对应 OAuth 功能开关。
