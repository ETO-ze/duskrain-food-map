# DuskRain 美食地图功能审计

审计日期：2026-07-12  
审计范围：公开首页、海外地图、评价页、超级管理员、作者工作台、后端接口、数据完整性、移动端适配与运行性能。

## 1. 系统边界

```text
浏览器
  -> Nginx / duskrain.cn/food-map/
      -> Authelia（仅超级管理员页面与接口，双因素）
      -> FastAPI :8091
          -> Vue 3 + Vite 构建产物
          -> SQLite 持久化数据
          -> 高德 Web 服务 API / JavaScript API
          -> Google Maps JavaScript API / Places / Geocoder
```

- 前端没有独立路由依赖，`App.vue` 根据当前路径挂载对应页面组件。
- FastAPI 同时提供静态页面入口和 JSON API。
- 地图瓦片由高德或 Google 直接提供，服务器不抓取、不镜像地图瓦片。
- 本站只持久化店家资料、个人评分、作者、图片 URL、评论和地图平台关联字段。

## 2. 页面与功能模块

| 页面 | 路径 | 主要能力 | 权限 | 审计状态 |
| --- | --- | --- | --- | --- |
| 国内公开地图 | `/food-map/` | 分类、推荐、城市、作者筛选；附近店家；随机探店；当前视野；列表/地图；日夜模式；店家卡片 | 公开 | 通过 |
| 海外公开地图 | `/food-map/global/` | Google 地图；国家/分类筛选；同步国内店家；附近店家；随机探店；当前视野；日夜模式 | 公开 | 通过 |
| 美食评价 | `/food-map/review/:id` | Markdown 评论、图片、店家摘要、缺失内容回退 | 公开，仅公开店家 | 通过 |
| 超级管理员 | `/food-map/admin/` | 店家库、搜索导入、批量新建、资料/评论编辑、作者账号、地图设置 | Authelia + TOTP | 通过 |
| 作者工作台 | `/food-map/developer/` | 我的店家、搜索新建、地图选点、批量新建、资料/评论编辑 | 应用账号 + HttpOnly Cookie | 通过 |

### 超级管理员模块

1. **店家库**：展示全部店家；按关键字和菜系定位；选择后进入编辑。
2. **搜索导入**：高德关键字与城市搜索；候选项明确选择后写入表单。
3. **批量新建**：解析“编号 店名 城市/地址 评分 推荐等级 作者 菜系”；多个菜系用“、”分隔，逐条匹配、去重、补全并保存。
4. **编辑资料**：编辑基础资料、归属作者、评分、推荐等级、图片和 Markdown 评论。
5. **作者账号**：创建、停用、重命名、重置首次登录临时密码；重命名同步迁移店家归属。
6. **地图设置**：国内/海外地图切换、日夜模式和地图选点。

### 作者工作台模块

1. **我的店家**：只返回当前作者数据，支持菜系筛选和快速编辑。
2. **搜索新建**：移动端与桌面端均可搜索高德候选，选择候选后自动补全。
3. **地图选点**：支持高德热点/坐标和 Google POI/反向地理编码。
4. **批量新建**：作者字段由当前账号固定，客户端不可代填其他作者。
5. **编辑资料**：只能新建、修改或删除归属自己的店家。

## 3. 权限与数据规则

- 超级管理员页面和 `/api/admin/*` 必须经过 Authelia `two_factor` 策略。
- 作者登录令牌保存在 HttpOnly Cookie；数据库只保存令牌 SHA-256 摘要。
- 作者密码使用 PBKDF2-HMAC-SHA256；首次登录必须修改临时密码；连续失败受限流保护。
- 作者接口依据会话中的作者身份查询，后端强制覆盖 `rating_author`，不能靠修改请求体越权。
- 更新或删除其他作者店家返回 404，不暴露目标记录详情。
- 同一平台 POI 可以由不同作者分别评价；同一作者重复添加同一店家时保留信息更完整的一条。
- 每家店可以保存多个去重菜系；旧 `my_category` 自动迁移为 `my_categories` 首项并继续兼容旧请求。
- 公开接口只返回 `is_public` 店家；不存在或已下架的评价返回清晰的中文提示。

## 4. 主要 API 分组

| 分组 | 接口 | 说明 |
| --- | --- | --- |
| 基础 | `GET /api/health`、`GET /api/config` | 健康检查和公开地图配置 |
| 公开数据 | `GET /api/places`、`GET /api/places/:id`、`GET /api/categories` | 公开店家、单店和筛选元数据 |
| 地图服务 | `GET /api/search`、`GET /api/regeo`、`GET /api/poi-detail` | 高德搜索、逆地理编码和详情补全；由超级管理员反向代理策略保护 |
| 作者会话 | `POST /api/developer/login`、`GET /session`、`POST /change-password`、`POST /logout` | 登录、首次改密和注销 |
| 作者店家 | `/api/developer/places*`、`/api/developer/search`、`/api/developer/regeo`、`/api/developer/poi-detail` | 带作者所有权约束的管理能力 |
| 超级管理 | `/api/admin/places*`、`/api/admin/authors*` | 全量店家和作者账号管理，反向代理层双因素保护 |

## 5. 本轮确认并修复的问题

- 修正超级管理员路径误用单因素策略的问题，页面和接口统一要求 TOTP。
- 修正移动端作者“搜索新建”无法命中真实候选的问题；高德检索改为优先无类型限制、强匹配判定、去重和相关性排序。
- 修正筛选并发响应乱序，以及分类变化后保留不可见城市/作者值导致空列表的问题。
- 修正公开数据缓存可能用旧空结果覆盖当前筛选的问题，改为网络优先、缓存失败回退。
- 修正 Google 随机探店和列表聚焦时信息窗体保持隐藏的问题。
- 修正超级管理员 Google 搜索候选预览使用无效 `InfoWindow` 参数的问题，改为锚定预览 Marker 打开。
- 修正 Google Advanced Marker 使用已弃用点击事件的问题。
- 修正高德聚合层在缩放停止后店家消失的问题；详细级别只维护一个官方聚合实例。
- 修正页面预热创建第二张隐藏高德地图、一次预取大量图片造成的流量和主线程压力。
- 修正店家图片混合内容 URL，并减少视口外列表的布局与绘制成本。
- 修正管理员切换模块后遗留上一模块状态提示的问题。
- 移除超级管理员高德地图重复注册的 Pointer/Mouse/Touch 拖动监听，只保留高德官方移动事件。
- 修正移动端列表横向溢出和桌面端隐藏按钮遮挡标题的问题。

## 7. 性能结果

- 公开首页冷加载从约 **149 个请求 / 34.7 MB** 降至约 **32 个请求 / 1.09 MB**。
- 去除隐藏地图预热后，公开页只保留一个高德地图容器和一个 Canvas 渲染上下文。
- 去除最多 80 张图片的主动预取，图片按实际进入视口加载。
- 低缩放级别使用城市汇总点；详细级别所有当前店家进入单个官方聚合层，避免按城市创建数十个聚合实例。
- 地图缩放只在跨越“城市汇总/店家详情”阈值时重建聚合，不在每个缩放事件重复重建。
- 服务器空闲资源充足，实测容器约 0.22% CPU、42 MiB 内存；当前主要瓶颈是浏览器地图 SDK、底图绘制和标记 DOM，而不是服务器算力。

## 8. 已知限制与待决项

- 高德 SDK 内部仍会输出 Canvas `willReadFrequently` 警告，来源不是本站代码，当前无业务错误。
- 中国东部低缩放级别城市密集时，圆点和数量全部保留；碰撞文字自动隐藏并可在悬停时查看。
- 海外页面当前主要验证的是同步国内店家；尚缺真实海外店家样本用于完整 CRUD 回归。
- 超级管理员频繁切换高德/Google 时两个地图实例会保留，可继续优化为销毁非活动实例。
- 当前 Vite 告警涉及开发服务器路径处理；生产容器只服务编译后的静态文件，不暴露 Vite 开发服务器。大版本升级需单独回归。
- 首页按钮和城市标签密度的改版方案需要产品确认后再实施。
